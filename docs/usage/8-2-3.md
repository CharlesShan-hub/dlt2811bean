# §8.2.3 Abort — 异常中止服务

## 概述

1. Abort 用于**强行断开**已关联的服务，客户端发送后服务器直接关闭关联，**不需要服务器响应**。
2. 可在 `reason` 中指定中止原因（`CODEDENUM` 类型），默认 reason=0 表示"其他原因"。
3. 服务器收到 Abort 后认为客户端已下线，会关闭 TCP 连接。

## 协议原文

### 服务参数

异常中止服务用于强行断开已关联的服务，服务的参数见表 21。

**表 21 异常中止服务参数**

| 服务/参数 | 数据类型 |
|-----------|----------|
| **Request** | |
| associationId | OCTETSTRING |
| reason | CODEDENUM |
| **Indication** | |
| associationId | OCTETSTRING |
| reason | CODEDENUM |

## 使用场景

### 1. 异常中止

```bash
cms> connect --ap C_B5041X/S1
  Connecting to 127.0.0.1:8102 ...
  Connected, negotiating parameters ...
  Negotiated, associating with C_B5041X/S1 ...
  OK  Associated: C_B5041X/S1

cms> abort
  OK  Abort sent (reason=0)
```

### 2. 指定中止原因

```bash
cms> connect --ap C_B5041X/S1
  OK  Associated: C_B5041X/S1
cms> abort --reason 1
  OK  Abort sent (reason=1)
```

### 3. JSON 模式

```bash
cms> abort --json
{"success":true,"message":"Abort sent (reason=0)"}
```

## 设计要点

- **Abort vs Release**：

| | Release | Abort |
|--|---------|-------|
| 方式 | 正常释放，双方协商 | 异常中止，单方面断开 |
| 响应 | 服务器返回响应 | **无响应**，单向报文 |
| 关联 ID | 需要携带 | 需要携带 |
| TCP 连接 | 保持 | 服务器端直接关闭 |
| 后续操作 | 可重新 associate | 需重新 connect |

- **单向报文**：Abort 是 CMS 协议中少数几个单向服务之一（另一个是 Report）。发送即结束，无确认机制。
- **服务器行为**：服务器收到 Abort 后立即清理会话状态（含 RCB 运行状态）、关闭关联、断开 TCP 连接。
