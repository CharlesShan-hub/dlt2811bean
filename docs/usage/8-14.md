# §8.14 TEST — 测试连接服务

## 概述

1. TEST 服务用于检测客户端与服务器之间的连接是否正常，相当于网络世界的 **ping/pong**。
2. 它是 CMS 协议中最简单的服务——**请求和响应都没有额外的字段**，只有帧头和服务代码。
3. 用来实现心跳机制，确认连接正常。
4. 不需要associate就可以发送的报文。

## 协议原文

测试服务用于通信连接的双方测试链路是否正常、对方是否能正确响应请求。当接收到Test帧时，应立刻返回一个Test帧。测试服务仅有APCH头，不含ASDU部分，帧长度FL=0。

## 协议细节

| 项目     | 值                          |
| ------ | -------------------------- |
| 服务代码   | `0xA1`（`ServiceName.TEST`） |
| 请求 PDU | 无（仅 reqId）                 |
| 响应 PDU | 无（仅 reqId）                 |
| 错误 PDU | 无                          |
| 方向     | 双向（客户端发起/服务端发起）            |

### 帧格式

```
请求: [FL:2][CC:0x01][SC:0xA1][FL-hi][FL-lo]   (FL=4, ASDU=0 bytes)
响应: [FL:2][CC:0x41][SC:0xA1][FL-hi][FL-lo]   (CC: bit6 Resp=1)
错误: [FL:2][CC:0x61][SC:0xA1][FL-hi][FL-lo]   (CC: bit6 Resp=1, bit5 Err=1)
```

## 使用场景

### 1. 手动测试连接

```bash
cms> connect --ap C_B5041X/S1
  Connecting to 127.0.0.1:8102 ...
  Connected, negotiating parameters ...
  Negotiated, associating with C_B5041X/S1 ...
  OK  Associated: C_B5041X/S1

cms> test
  OK  Ping/pong OK
```

### 2. JSON 模式

```bash
cms> test --json
{"success":true,"message":"Ping/pong OK"}
```

### 3. 服务端保活心跳（自动）

TEST 由 `KeepAliveManager` 自动发送，不需要用户手动操作。当服务端检测到会话空闲超过 `idleTimeoutMs` 时，自动发送 TEST 探测：

```
服务端探测流程：
  空闲 > idleTimeoutMs
    → 发送 TEST 请求（req）
    → 客户端自动回复 TEST 响应（resp/pong）
    → 收到响应，重置空闲计时器
    → 超过 maxRetries 次无响应 → 断开连接
```

配置（`application.yaml`）：

```yaml
server:
  keepalive:
    idleTimeoutMs: 30000     # 空闲多久开始探测 (ms)
    retryIntervalMs: 5000    # 探测重试间隔 (ms)
    maxRetries: 4            # 最大重试次数
```
