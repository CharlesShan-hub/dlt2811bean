# §8.7.5 SetURCBValues — 设置非缓存报告控制块值服务

## 概述

1. 修改非缓存报告控制块（URCB）的属性。
2. 启用报告后，数据变化时服务器自动推送 Report。
3. 对应 CLI 命令：`set-urcb-vals`

## 协议原文

##### 8.7.5.1 服务参数

设置非缓存报告控制块值服务用于修改非缓存报告控制块内的一个或多个属性，服务的参数见表 50。

**表 50 设置非缓存报告控制块值服务参数**

| 服务/参数 | 数据类型 |
|-----------|----------|
| **Request** | |
| urcbReference | ObjectReference |
| rptID[0..1] | VisibleString129 |
| rptEna[0..1] | BOOLEAN |
| datSet[0..1] | ObjectReference |
| confRev[0..1] | INT32U |
| optFlds[0..1] | RcbOptFlds |
| bufTm[0..1] | INT32U |
| intgPd[0..1] | INT32U |
| gi[0..1] | BOOLEAN |
| **Response+** | |
| result | ServiceError |
| **Response-** | |
| serviceError | ServiceError |

##### 8.7.5.2 服务要求

设置非缓存报告控制块值的服务要求如下。

a) 除 rptEna 外，其他属性之间没有顺序要求，某一个属性设置失败应不影响其他属性设置。

b) 设置序列中含有 rptEna 且其值为 False 时，应先设置 rptEna 为 False 再设置其他属性。rptEna 值为 True 时，应先设置其他属性再设置 rptEna。属性设置未全部成功的情况下，应不继续设置 rptEna 值为 True。

c) 设置序列为空时，应返回 Response+，不对非缓存报告控制块做任何修改。

d) 所有控制块均设置成功时返回 Response+，部分或全部失败时返回 Response-。在 Response-中，无论设置成功或失败，应返回每个控制块的设置结果。

e) 某控制块的所有属性均设置成功的情况下，该控制块 result 的内容应为空。某控制块的部分属性设置失败的情况下，该控制块 result 中应包含设置失败的属性，设置成功的属性不需列入。

## 使用场景

```bash
cms> connect --ap P_B5041A/S1
cms> get-urcb-vals --refs "LD0/LLN0.urcbAin"
  URCB values (1 items):
    [0] LD0/LLN0.urcbAin  rptID=LD0/LLN0$RP$urcbAin ...
cms> set-urcb-vals --ref LD0/LLN0.urcbAin --rpt-id "MyCustomRptID"
  Setting URCB values: ref=LD0/LLN0.urcbAin
  OK  URCB values set for LD0/LLN0.urcbAin
cms> set-urcb-vals --ref LD0/LLN0.urcbAin --buf-tm 5000 --intg-pd 30000
  OK  URCB values set for LD0/LLN0.urcbAin
cms> set-urcb-vals --ref LD0/LLN0.urcbAin --rpt-ena true
  OK  URCB values set for LD0/LLN0.urcbAin
cms> set-urcb-vals --ref LD0/LLN0.urcbAin --gi true
  OK  URCB values set for LD0/LLN0.urcbAin
# 收到推送
  Report Received: rptID=LD0/LLN0$RP$urcbAin sqNum=1 ...
```
