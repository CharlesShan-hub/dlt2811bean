# §8.2.2 Release — 释放关联服务

## 概述

1. Release 用于**正常关闭**已建立的关联。释放后可以重新 `associate` 更换访问点。
2. 释放时需要携带 `associationId`，服务器确认后关闭关联，TCP 连接保持。
3. 释放后若需再次通信，只需重新 `associate` 即可，无需重新 `connect`。

## 协议原文

### 服务参数

释放关联服务用于关闭已建立的关联，服务的参数见表 20。

**表 20 释放关联服务参数**

| 服务/参数 | 数据类型 |
|-----------|----------|
| **Request** | |
| associationId | OCTETSTRING |
| **Response+** | |
| associationId | OCTETSTRING |
| result | ServiceError = no-error |
| **Response-** | |
| serviceError | ServiceError |

## 使用场景

### 1. 正常释放

```bash
cms> connect --ap C_B5041X/S1
  Connecting to 127.0.0.1:8102 ...
  Connected, negotiating parameters ...
  Negotiated, associating with C_B5041X/S1 ...
  OK  Associated: C_B5041X/S1

cms> release
  OK  Released.
```

### 2. 释放后重新关联

Release 只是释放关联，不会断开 TCP 连接。释放后可以立即重新 associate 到另一个访问点：

```bash
cms> connect --ap C_B5041X/S1
  OK  Associated: C_B5041X/S1
cms> release
  OK  Released.
cms> associate --ap P_B5041A/S1
  OK  Associated: P_B5041A/S1
```

### 3. JSON 模式

```bash
cms> release --json
{"success":true,"message":"Released."}
```

## 设计要点

- **Release vs Disconnect**：release 只释放应用层关联，TCP 连接保持。`disconnect` 关闭整个 TCP 连接。
- **释放后可换 AP**：release 后可以不带 `--ap` 直接 `associate` 使用默认访问点，也可指定新的访问点。
- **释放前必须已关联**：未关联时调用 release 会返回错误。
